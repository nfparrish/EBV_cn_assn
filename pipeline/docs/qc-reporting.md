# Phase 1 QC Reporting Contract

This document defines the output contract for Phase 1 QC generation and cohort aggregation.

## Output Artifacts

- `*.qc.json` — one per sample, generated by `QC_SAMPLE`
- `qc_cohort_metrics.tsv` — cohort-wide machine-readable table
- `qc_cohort_summary.json` — cohort-level summary statistics
- `qc_cohort_report.md` — human-readable markdown report
- `sample_status_registry.tsv` — processed/skipped registry for resumable runs

## Per-Sample QC Fields

Each sample QC JSON includes:

- `sample_id`
- `status` (`processed` or `skipped`)
- `dataset`, `population`, `sequence_lab`
- `metrics.read_count`
- `metrics.q30_rate`
- `metrics.mapping_rate`
- `metrics.mean_coverage`
- `warnings` (e.g., `low_coverage`, `low_q30`)

## Cohort Summary Fields

`qc_cohort_summary.json` includes:

- `sample_count`
- `status_counts.processed`
- `status_counts.skipped`
- mean metrics (`q30_rate_mean`, `mapping_rate_mean`, `mean_coverage_mean`)
- warning tallies (`low_coverage`, `low_q30`)

## Interpretation Guidance (Warning-First)

Phase 1 does not hard-filter samples. Instead, warnings are emitted for review:

- `low_coverage` if mean coverage is below default readiness range
- `low_q30` if base quality is below warning threshold

Hard exclusion policies can be introduced in later phases after pilot validation.
